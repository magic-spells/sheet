@magic-spells/sheet

Every edge, and a spring home.

Bottom, left, right, or a card floating clear of all four sides. Bottom-sheet snap points you can drag between, flicks that step exactly one, and a real spring — not a transition — carrying every landing.

Snap 20vh · 55vh · 90vh

Three heights, and the sheet lands on one.

snap-points="20vh 55vh 90vh" gives the sheet several resting heights — any CSS length, re-measured on resize. Drag between them from the header, the backdrop, or the content once it hits its scroll top. A flick past 0.5 px/ms steps exactly one snap, a slow release lands on the nearest, and a downward flick from the lowest snap dismisses. Snap points are a mobile-profile attribute: past breakpoint the list is ignored and the panel carries a single resting size.

Not open yet… 
<sheet-panel snap-points="20vh 55vh 90vh" initial-snap="1">…</sheet-panel>

// index, not length — the snap list is ordered as written
sheet.activeSnap;      // 1
sheet.snapTo(2);       // spring up to 90vh

sheet.addEventListener('snapchange', ({ detail }) => {
  console.log(detail); // { from: 1, to: 2 }
});

Edges bottom · left · right

The same gesture, turned ninety degrees.

position="left" or position="right" turns the drag horizontal and dismisses toward the edge the sheet came from. A side sheet has one fixed width — the --sheet-active-size token — and ignores snap-points. Both demos pin the mobile profile with breakpoint="9999" so you can try them here. 

<sheet-panel position="left">…</sheet-panel>

<sheet-panel position="right" effect="slide-fade">…</sheet-panel>

/* Optional fixed-width override. No width attribute is needed. */
#left-panel > dialog {
  --sheet-active-size: 24rem;
}
Card 12px on all sides · 20px radius

Detach it, and the corners stop clashing.

mode="card" is the same bottom sheet, inset by --sheet-card-margin on the left, right and bottom, with all four corners rounded. Edge mode matches the platform's own sheets; the card reads as a floating object instead. Both buttons open the same queue — same snaps, same gestures, different geometry. 

<!-- edge · flush to the bottom, two corners rounded -->
<sheet-panel position="bottom" snap-points="45vh 80vh">…</sheet-panel>

<!-- inset card · detached on three sides, all four corners -->
<sheet-panel position="bottom" mode="card" effect="fade-scale" snap-points="45vh 80vh">…</sheet-panel>

/* sheet.css — geometry only, no script reads it */
dialog-panel[morph][state]:has(sheet-panel[data-mode='card'][data-position='bottom']) > dialog {
  inset: auto var(--sheet-card-margin) var(--sheet-card-margin); /* right · bottom · left */
  max-width: calc(100vw - 2 * var(--sheet-card-margin));
  border-radius: var(--sheet-card-border-radius);
  padding-bottom: 0; /* the margin already clears the safe area */
}

/* set the gap yourself — 12px reads well down to a 375px viewport */
:root { --sheet-card-margin: 12px; --sheet-card-border-radius: 20px; }
Responsive breakpoint 768 · morph 600ms

A bottom sheet on a phone. Something else entirely on a desktop.

Below breakpoint — 768px by default — the mobile position, mode and effect apply. At or above it, their desktop-* twins take over. Resize across 768px while a sheet is open and it morphs to the new geometry in place: no close and reopen, no lost focus, no lifecycle events. Unset values inherit down the column, with two exceptions. A bottom sheet becomes a centred dialog on the desktop, because a floating card in the middle of the screen is what a desktop dialog reads as — say desktop-position="bottom" to keep it on the edge, where it sizes to its content too. And desktop-mode never reads mode at all: absent, a desktop panel is always a card, whatever the mobile profile does. snap-points stops applying entirely past the breakpoint: every desktop profile is dismiss-only, with one resting size taken from its content (bottom and centre) or from a CSS token (the sides).

Effects 3 named · 1 spring

Three ways to arrive.

An effect is how the sheet arrives. slide travels in from its edge, slide-fade fades across a short 24px slide, and fade-scale fades up in place. The three cards below are identical apart from the attribute. 

<sheet-panel effect="slide-fade" desktop-effect="fade-scale">…</sheet-panel>

// sheet-engine.js — the hidden endpoint, per effect
if (hidden && effect === 'slide')      distance = size + inset + cushion;
if (hidden && effect === 'slide-fade') distance = 24,   opacity = 0;
if (hidden && effect === 'fade-scale') scale    = 0.95, opacity = 0;
Leaving one runway · own effect · lockable

How a sheet leaves.

A dismissal starts wherever your finger let go, and it always clears the screen fully — the panel's own size, plus any gap it floats by, plus a shadow cushion (--sheet-exit-cushion). exit-effect lets leaving differ from arriving: drag the second card down and it keeps going the way your finger was moving, then shrinks away.

And sometimes a sheet must not be waved away. dismiss="none" closes the swipe, backdrop and Escape routes but keeps the buttons working — the panel still tracks your finger, springs back, and reports each refusal through snaprelease.

Not open yet… 
<sheet-panel effect="slide" exit-effect="fade-scale">…</sheet-panel>

// swipe, backdrop and Escape refused; buttons still work
<sheet-panel dismiss="none">…</sheet-panel>

// or open just some of them
<sheet-panel dismiss="backdrop escape">…</sheet-panel>

// sheet-engine.js — an exit never ends closer to rest than it started
const floor = away > 0 ? away + cushion : 0;
Footer flex-shrink: 0

The bar stays put while the list moves.

Add <sheet-footer> and the sheet becomes a three-part column: header and footer hold still, only the content between them scrolls. The footer takes over the safe-area padding so its background runs to the bottom of the screen, and it is a drag surface on the same terms as the header. 

<sheet-panel snap-points="35vh 75vh">
  <sheet-header>…</sheet-header>   /* rigid · drag surface */
  <sheet-content>…</sheet-content> /* flex: 1 · scrolls    */
  <sheet-footer>
    <button>Place order</button>
  </sheet-footer> /* rigid · owns the safe area */
</sheet-panel>

/* sheet.css */
sheet-panel[data-position='bottom'] sheet-footer {
  padding-bottom: calc(var(--sheet-footer-padding) + env(safe-area-inset-bottom, 0px));
}
Lifecycle 4 + 2 events

Every open, close and landing leaves a mark.

Four lifecycle events come from the parent <dialog-panel>; snapchange and snaprelease come from the sheet. All six bubble, so one listener sees the whole cycle, and snapchange fires on commit — never mid-drag. The log below is wired to every panel on this page. 

Events log
const panel = document.querySelector('#account-panel');

for (const name of ['beforeShow', 'shown', 'beforeHide', 'hidden']) {
  panel.addEventListener(name, () => console.log(name));
}

// bubbles up from the sheet, on commit only
panel.addEventListener('snapchange', ({ detail }) => {
  console.log(`snap ${detail.from} → ${detail.to}`);
});

// cancelable — this sheet refuses to open
panel.addEventListener('beforeShow', (event) => event.preventDefault());
Lab mobile + desktop · exits · morph · routes · 2 dials

Set the dials, and read back the markup.

Four positions, two geometries and four effects make thirty-two profiles of one panel — and the mobile and desktop halves are dialled separately, split at the real 768px breakpoint. Every setting is a plain attribute or CSS token, no config object. Leave a desktop dial on inherit and it falls back the documented way: position takes the mobile one — except a bottom, which becomes a centred dialog — and the effects follow their chains. Mode is the one that inherits nothing, which is why its switch reads card (default) instead: on a wide viewport the sheet floats as a card whatever mode says. The snap switches are a mobile dial: past the breakpoint the panel drops to one resting size, and a desktop bottom takes that size from its own content, just like a centre. Set the dials, then open: the snippet below is re-read from the element itself, so it always shows the real DOM. Resize across the breakpoint with the panel open and it morphs between your two configurations in place. The spring dials govern entrances only; exits and snaps keep their presets.

Accessibility

				

					Modal semantics, focus trapping, focus return, Escape handling and body scroll lock are
					delegated to the native <dialog> through the parent panel — the sheet
					adds no ARIA of its own. Give every dialog an accessible name with
					aria-labelledby or aria-label, label icon-only buttons, keep a
					visible close control, and pass the real opener to show(). Any element with
					data-action-hide-dialog closes the sheet.
				

				

					Never make a drag the only route to an action. Interactive descendants stay clickable
					because pointer capture is deferred until movement passes 5px, and a backdrop
					gesture under 10px and 300ms is read as a tap rather than a
					drag.
				


				
Browser support

				

					Modern browsers with custom elements, native <dialog>, Pointer Events,
					:has(), custom properties and dvh. Pointer Events mean mouse,
					pen and touch all take the same path, so every drag on this page works with a mouse.
